# Complete replacement: Muslim Pedia → CatatinAja personal finance PWA

The codebase is entirely replaced — from a Quran reader to a mobile-first personal finance tracker. The app uses vanilla HTML/CSS/JS with an IIFE module pattern, localStorage persistence, hash-based routing, and Chart.js for visualizations. It covers transaction CRUD, multi-dimension filtering, budget management per category, CSV/JSON export/import, and a three-tab reports page with charts.

Watch for: XSS via `innerHTML` rendering of user-supplied transaction descriptions (confirmed), data import replaces all data without structural validation (confirmed), service worker's `type === 'basic'` guard guarantees CDN resources are never cached — charts and icons break offline (confirmed), and `parseInt` for amount parsing silently truncates decimal inputs (confirmed).

## High-level view

Three IIFE modules (`DataModule`, `StorageModule`, `App`) provide data constants, localStorage abstraction, and UI controller logic. The single-HTML-file approach with hash routing works for a no-build PWA, but the 1100-line controller uses innerHTML-based rendering throughout, creating an XSS surface wherever user-supplied data (descriptions, imported records) is interpolated.

The storage layer wraps localStorage with try/catch but returns silently on write failures — the UI never learns that a save failed. Budget data is keyed by category display name, creating a coupling where renaming a category in `DataModule` orphans stored budgets.

The service worker's fetch handler only caches responses where `networkResponse.type === 'basic'`, which excludes all CDN resources (Chart.js, Font Awesome, Google Fonts). These are guaranteed to be unavailable offline despite the cache-first strategy.

The import path validates the presence of top-level keys but not their types or record shapes, so a corrupted import crashes the app on next render.

5. **No service worker update path** — Cache-first strategy serves stale HTML; no update prompt or reload-on-activate logic exists. Users can be stuck on old code indefinitely.
6. **Decimal amounts silently truncated** — `parseInt` on the amount field drops decimals (e.g., "50000.5" → 50000) without user feedback. Consider `Math.round` or rejecting non-integer input explicitly.
7. **Budget keyed by display name** — Budgets are stored with `category: "Makanan & Minuman"`. If the display name in `DataModule` changes, stored budgets become invisible.

## XSS surface in innerHTML rendering

`createTransactionItem` builds anchor elements by interpolating `t.description` and `t.category` directly into an HTML template string:

```javascript
<span class="transaction-desc">${t.description || ''}</span>
```

Both values come from user input (the add/edit form) and from the JSON import path. A crafted import file containing `<img src=x onerror=alert(1)>` as a description would execute script in the user's browser context. The description field should be escaped before insertion, or the rendering should use DOM APIs (`textContent` assignment) instead of innerHTML.

## Storage failure goes unnoticed

`StorageModule.setItem` catches exceptions and returns `false`, but `addTransaction`, `updateTransaction`, and `deleteTransaction` never inspect that return value. On mobile browsers where localStorage is limited (especially in private browsing where some browsers allow 0 bytes), a write failure means the user sees a success (redirect to `#home`) while the data is lost.

## Offline gap: CDN resources excluded by type guard

The service worker's fetch handler has this condition:

```javascript
if (networkResponse && networkResponse.status === 200 && networkResponse.type === 'basic') {
```

CDN responses (Chart.js, Font Awesome, Google Fonts) arrive as `type: 'cors'`, so they are never stored in the cache. This isn't a matter of missing them from `STATIC_ASSETS` — the runtime caching path explicitly rejects them. After the service worker activates, an offline user gets a broken reports page (no Chart.js), missing icons (no Font Awesome), and fallback fonts. Fix by removing the `type === 'basic'` guard or by adding CDN URLs to the precache list with `{ mode: 'cors' }` fetch options.

## Import validation gap

`handleImportJSON` checks for the existence of `data.transactions` or `data.budgets`:

```javascript
if (!data.transactions && !data.budgets) {
    alert('Format file tidak valid...');
    return;
}
```

It doesn't validate that `data.transactions` is an array, that each element has required fields (`id`, `type`, `amount`, `category`, `date`), or that amounts are numbers. A file containing `{"transactions": "not an array"}` passes validation and then crashes every `.filter()` and `.forEach()` in the app.

## Mini-chart repeated JSON parsing

`renderMiniChart` calls `StorageModule.getTransactions()` inside a loop (7 iterations for 7 days):

```javascript
for (let i = 6; i >= 0; i--) {
    const transactions = StorageModule.getTransactions();
    const dayExpense = transactions.filter(...).reduce(...);
}
```

Each call parses the entire localStorage JSON blob. With a large transaction history, this runs 7 full parses + 7 full array scans. The data should be fetched once before the loop.

## Budget data coupling to display names

Budget records use the category display name as the key:

```javascript
const budget = budgets.find(b => b.category === cat.name && b.month === currentMonthStr);
```

If `DataModule` renames a category or adds localization, stored budgets silently disappear. Using the category `id` field instead would decouple persistence from presentation. Acceptable for v1 but creates a migration burden later.
